# Вклад в Mirage

## Ветки

- `main` — только принятые релизы;
- `dev` — интеграционная ветка Mirage 2.0;
- рабочая ветка создаётся от актуального `dev` и возвращается pull request’ом в
  `dev`;
- релиз оформляется отдельным PR `dev → main`; прямой push в `main` запрещён.

Перед началом работы синхронизируйте ветку без force-push:

```bash
git switch dev
git pull --ff-only origin dev
git switch -c docs/short-description
```

## Коммиты и проверки

Используйте Conventional Commits на русском языке:

```text
тип(область): краткое описание
```

Каждый логически завершённый этап должен иметь отдельный коммит. Перед PR
запустите полный gate:

```bash
bash ops/release/check-local.sh
```

PR содержит цель изменения, проверенные сценарии и известные ограничения.
История этапных коммитов сохраняется; squash-merge для релизной ветки не
используется.

## Секреты и документация

Не добавляйте в Git токены, пароли, SSH-ключи, сертификаты, реальные IP и
домены, UUID, ссылки подписок или архивы. Любое изменение поведения должно
обновлять русскую и английскую публичную документацию одновременно.

Правила архитектуры, допустимой автоматизации и аудита находятся во внешнем
`PLAN.md`; Marzban настраивается только по его официальной документации.
