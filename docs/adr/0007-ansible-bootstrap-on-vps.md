# 7. Первый Ansible-bootstrap запускать прямо на VPS

- **Статус:** принято
- **Дата:** 2026-06-27

## Контекст

После первой попытки hardening SSH пользователь случайно заблокировал себе доступ
к VPS. Сервер переустановлен, доступ восстановлен. Главный риск на этом этапе —
снова потерять SSH до того, как доступ по ключу проверен в отдельной сессии.

По [ADR-0006](0006-manual-provisioning-defer-terraform.md) Terraform отложен, а
Ansible остаётся ближайшей целью. Локальная машина пользователя — Windows. Можно
поднимать WSL или использовать отдельную Linux VM, но для первого bootstrap это
добавляет лишний слой настройки.

## Решение

Первый Ansible-bootstrap запускаем **прямо на свежем VPS** и применяем к
`localhost` через `connection: local`.

Playbook делает безопасный минимум:

- бэкапит административные файлы перед изменениями;
- создаёт отдельного пользователя `mirage` с sudo;
- ставит публичный SSH-ключ;
- настраивает базовый firewall и `fail2ban`;
- включает SSH-hardening только отдельным флагом после проверки входа по ключу;
- перед SSH-hardening создаёт rollback-таймер через `systemd-run`.

Пароль от VPS используется только для первого входа через SSH или консоль
провайдера. Пароль, приватный ключ, реальные IP и inventory с доступами не
попадают в git.

## Рассмотренные альтернативы

- **WSL Ubuntu на Windows** — хорошая постоянная control node, но требует отдельной
  настройки до решения срочной задачи восстановления безопасного доступа.
- **Локальная Linux VM** — тоже рабочий вариант, но первый bootstrap проще сделать
  прямо на сервере, где уже есть root-доступ.
- **Bash-скрипт по SSH** — быстрее, но хуже ложится в будущую модель
  configuration management и сложнее поддерживает идемпотентность.

## Последствия

- **Плюс:** меньше движущихся частей на первом восстановительном этапе.
- **Плюс:** Ansible появляется сразу, без промежуточного bash-скрипта.
- **Плюс:** SSH-hardening становится двухфазным и откатываемым.
- **Минус:** VPS временно становится и target, и control node. Это bootstrap-
  компромисс, а не финальная production-модель.
- **Минус:** при полной переустановке сервера Ansible и репозиторий нужно снова
  загрузить на VPS. Позже control node можно перенести на отдельную Linux-машину.
