# 1. Вести журнал архитектурных решений (ADR)

- **Статус:** принято
- **Дата:** 2026-06-25

## Контекст

В проекте будут приниматься решения с долгими последствиями: какой протокол VPN,
как устроена миграция между серверами, чем провижинить инфраструктуру. Через
несколько месяцев легко забыть, *почему* выбрали именно так, и случайно откатить
осознанный выбор.

## Решение

Каждое значимое архитектурное решение фиксируем отдельным файлом в `docs/adr/` по
шаблону [template.md](template.md). Формат — лёгкий
[MADR](https://adr.github.io/madr/): контекст, решение, последствия.

- Файлы нумеруются по порядку: `0002-...`, `0003-...`.
- ADR **неизменяем**: если решение пересмотрено — заводим новый ADR и помечаем
  старый статусом «заменён ADR-XXXX».

## Последствия

- **Плюс:** видна история и мотивация решений; легче сопровождать проект и
  возвращаться к прежним компромиссам.
- **Плюс:** дисциплина думать о последствиях до реализации.
- **Минус:** небольшая накладная работа на каждое крупное решение — осознанно идём
  на это.
