# 6. Пересмотр: ручной provisioning (reseller-VPS), Terraform отложен

- **Статус:** принято
- **Дата:** 2026-06-25
- **Пересматривает:** [ADR-0004](0004-iac-from-the-start.md), [ADR-0005](0005-vps-provider-timeweb.md)

## Контекст

Европейские серверы у Timeweb ([ADR-0005](0005-vps-provider-timeweb.md)) оказались
дорогими. Вместо этого куплен VPS у ритейлера (магазин-перепродавец): Германия
(Франкфурт), ~796 ₽/мес, оплата картой РФ. У такого сервера **нет API
провайдера** — доступы выдаются вручную (IP, root, пароль).

Без API невозможен provisioning через Terraform, а значит пересматриваются
[ADR-0004](0004-iac-from-the-start.md) (IaC с самого начала) и
[ADR-0005](0005-vps-provider-timeweb.md) (провайдер Timeweb).

## Решение

- **Провайдер** — reseller-VPS (Германия, Франкфурт). Provisioning **ручной**.
- **Terraform — отложен** до будущих версий (когда/если переедем на провайдера с
  API; заодно это путь к более нейтральной юрисдикции).
- **Ansible — остаётся ближайшей целью.** Он настраивает сервер по SSH и не требует
  API, поэтому сохраняет половину IaC и быструю часть миграции. Порядок: сначала
  поднять стек **вручную** (понять каждый шаг), затем кодифицировать в Ansible.
- **Сейчас** — ручная настройка по учебному гайду (Часть II).

## Последствия

- **Плюс:** дешевле; быстрый старт; рабочий результат — приоритет №1.
- **Минус (миграция):** при бане IP новый сервер покупается **вручную** у ритейлера,
  а не `terraform apply`. Автоматизируется только настройка (Ansible) +
  восстановление `x-ui.db` + переключение DNS. «Переезд в одну команду» становится
  «переезд за несколько ручных шагов».
- **Минус (риски ритейлера):** возможны «грязные» IP, недолговечность продавца, root
  по паролю, отсутствие возврата. → **Бэкап `x-ui.db` и готовность к миграции
  критичны именно сейчас.**
- **Юрисдикция:** аплинк ритейлера неизвестен; профиль держим низким (личное
  использование, узкий круг).
