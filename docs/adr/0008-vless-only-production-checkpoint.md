# 8. Production-checkpoint: VLESS Reality only

- **Статус:** принято
- **Дата:** 2026-06-28

## Контекст

После запуска 3x-ui/Xray рабочий профиль `VLESS + Reality + XTLS-Vision` на
`443/tcp` успешно прошёл проверку в клиенте. Панель 3x-ui закрыта за
SSH-туннелем, пароль панели и клиентский профиль ротированы, backup сохранён вне
git.

Shadowsocks-2022 проверялся как резервный inbound на `8388/tcp`, но не стал
частью рабочей схемы: порт был доступен снаружи, Xray принимал соединения, но
клиентский тест заканчивался timeout. Поэтому держать публичный `8388/tcp`
открытым без подтверждённого рабочего профиля нельзя.

## Решение

Текущий production-checkpoint Mirage:

- `22/tcp` — SSH по ключу;
- `443/tcp` — Xray VLESS Reality;
- панель 3x-ui — только `127.0.0.1:ПОРТ_ПАНЕЛИ` через SSH-туннель;
- `8388/tcp` — закрыт;
- резервный протокол выбирается и проверяется отдельным этапом.

Ansible-bootstrap по умолчанию открывает только `22/tcp` и `443/tcp`, а
неиспользуемые резервные порты держит закрытыми.

## Последствия

- **Плюс:** минимальная публичная поверхность атаки.
- **Плюс:** повторный bootstrap не возвращает неиспользуемый `8388/tcp`.
- **Плюс:** документация отражает фактическое рабочее состояние.
- **Минус:** резервного протокола пока нет; при проблемах с VLESS Reality нужна
  миграция на новый VPS или отдельная проверка нового резервного профиля.
- **Компенсация:** домен, subscription-ссылки и backup сохраняют быстрый путь к
  переезду на новый VPS.
