# 4. Инфраструктура как код с самого начала (Terraform + Ansible)

- **Статус:** пересмотрен [ADR-0006](0006-manual-provisioning-defer-terraform.md) (Terraform отложен; Ansible остаётся)
- **Дата:** 2026-06-25

## Контекст

Цель «переезд в одну команду» требует, чтобы сервер был воспроизводим. Есть две
стратегии: сначала всё руками и позже кодифицировать, либо IaC сразу.

## Решение

Вводим **Terraform** (провижининг VPS, DNS, firewall) и **Ansible** (установка и
настройка сервисов) с самого начала проекта.

Чтобы избежать непрозрачной автоматизации, каждый ресурс Terraform и каждую
таску Ansible документируем по смыслу до запуска.

## Рассмотренные альтернативы

- **Сначала вручную, потом кодифицировать** — проще на старте и нагляднее, но даёт
  ручной дрейф конфигурации и откладывает цель воспроизводимости. Отклонено по
  выбору пользователя.

## Последствия

- **Плюс:** сервер воспроизводим с первого дня; миграция становится быстрее.
- **Плюс:** конфигурация под версионным контролем и ревью.
- **Минус:** выше входной порог; требуется дисциплина документировать изменения
  до применения.
- **Минус:** секреты в Ansible нужно сразу класть в Vault, а не в открытый код.
