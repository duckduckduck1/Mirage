# 3. Доставка через подписку и миграция через домен + бэкап

- **Статус:** принято
- **Дата:** 2026-06-25

## Контекст

Главный приоритет проекта — смена сервера/IP без ручной перенастройки клиентов.
Блокировки IP происходят регулярно, переезд должен быть рутиной, а не авралом с
рассылкой новых конфигов.

## Решение

Клиентам выдаём **subscription-ссылку**, а не голый конфиг. Подписку отдаёт сам
VPS (3x-ui), но адрес ссылки привязан к **домену** `sub.ДОМЕН`, а не к IP.

Переезд на новый сервер:

1. Поднять новый VPS вручную или через Terraform, когда появится провайдер с API.
2. Настроить базовый доступ через Ansible.
3. Восстановить базу 3x-ui из бэкапа — те же клиенты и UUID.
4. Переключить A-запись `sub.ДОМЕН` на новый IP (низкий TTL DNS).
5. Клиенты при обновлении подписки сами переходят на новый сервер.

## Рассмотренные альтернативы

- **Прямые клиентские конфиги** — при смене IP мертвы, нужна рассылка всем. Отказ.
- **Подписка по IP без домена** — переезд снова рвёт ссылку. Отказ.
- **Отдельный always-on control-хост для подписок** — надёжнее (VPN-сервер
  полностью одноразовый), но сложнее и дороже. Отложено как возможное улучшение.

## Последствия

- **Плюс:** переезд незаметен для клиентов; IP становится расходником.
- **Плюс:** домен даёт заодно валидный TLS-сертификат для подписки.
- **Минус:** нужен домен и управляемый DNS; при переезде обязателен восстановленный
  бэкап базы 3x-ui, иначе подписки разъедутся. Бэкап — критичный артефакт.
