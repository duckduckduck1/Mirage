# Домен и subscription-ссылки

Runbook описывает, как подключить домен к Mirage и подготовить стабильную выдачу
клиентских профилей. Домен не защищает VPS от блокировки по IP, но упрощает
переезд: при смене сервера ты меняешь DNS, а клиенты продолжают использовать
старый адрес профиля или подписки.

Не добавляй в git реальные IP, домен, `vless://`-ссылки, UUID, API-токены,
приватные ключи Reality, пароль панели и backup-файлы.

## Целевая схема

```text
vpn.ДОМЕН   A   SERVER_IP   # адрес подключения VLESS Reality
sub.ДОМЕН   A   SERVER_IP   # subscription endpoint, когда он включён
```

`vpn.ДОМЕН` нужен уже сейчас: клиентский профиль вида
`vless://...@vpn.ДОМЕН:443?...` переживает смену IP, если на новом VPS
восстановлены те же клиенты, ключи Reality и inbound'ы.

`sub.ДОМЕН` нужен для централизованной выдачи профилей. Через подписку удобно
добавлять резервные inbound'ы, отключать клиентов, менять адрес сервера и
обновлять конфигурацию без ручной пересылки отдельных ссылок.

## Что купить и где держать DNS

Купи обычный домен у регистратора, где удобно управлять DNS-зоной. Для Mirage не
нужен дорогой домен: важны доступ к DNS, низкий TTL и возможность быстро поменять
A-записи.

Можно использовать Cloudflare или DNS-панель регистратора. Если используешь
Cloudflare:

- держи `vpn.ДОМЕН` в режиме **DNS only**;
- не включай proxy для Reality и другого произвольного TCP-трафика;
- для `sub.ДОМЕН` включай proxy только если endpoint обслуживает обычный
  HTTP/HTTPS на поддерживаемом порту и ты понимаешь TLS-схему;
- не храни Cloudflare API token в репозитории.

Cloudflare проксирует не любой TCP-сервис. Для TCP/UDP приложений вне обычного
HTTP/HTTPS нужен отдельный продукт Spectrum, а для неподдерживаемых портов
Cloudflare рекомендует серый режим DNS only или Spectrum.

## Настройка DNS

1. Открой DNS-зону домена.
2. Создай запись для VPN:

   ```text
   Type: A
   Name: vpn
   Value: SERVER_IP
   TTL: 60–300
   Proxy status: DNS only
   ```

3. Создай запись для будущей подписки:

   ```text
   Type: A
   Name: sub
   Value: SERVER_IP
   TTL: 60–300
   Proxy status: DNS only
   ```

4. Подожди обновления DNS.

Проверь с локальной Windows-машины:

```powershell
Resolve-DnsName vpn.ДОМЕН
Resolve-DnsName sub.ДОМЕН
Test-NetConnection vpn.ДОМЕН -Port 443
```

Проверь с Linux/macOS:

```bash
dig +short vpn.ДОМЕН
dig +short sub.ДОМЕН
```

Ожидаемо: DNS возвращает `SERVER_IP`, а порт `443` доступен.

## Перевод VLESS Reality на домен

Сначала переведи основной клиентский профиль на `vpn.ДОМЕН`. Это даёт быстрый
выигрыш даже без публичной подписки.

1. Открой панель 3x-ui через SSH-туннель.
2. Перейди в **Входящие**.
3. Открой inbound `vless-reality-vision`.
4. На вкладке **Основное** найди поле, которое отвечает за адрес в ссылках.
   В разных версиях 3x-ui оно может называться **Стратегия адреса для ссылок**,
   **Адрес прослушивания inbound**, **Публичный адрес** или **Адрес для ссылок**.
5. Выбери пользовательский адрес, если такая стратегия доступна.
6. Укажи:

   ```text
   vpn.ДОМЕН
   ```

7. Сохрани inbound.
8. Экспортируй одиночную `vless://`-ссылку заново.
9. Проверь в локальном текстовом редакторе, что ссылка содержит:

   ```text
   @vpn.ДОМЕН:443
   security=reality
   flow=xtls-rprx-vision
   ```

10. Импортируй профиль в Hiddify и проверь подключение.

Если клиент показывает старый IP, ссылка экспортирована до смены адреса inbound.
Сохрани inbound и скопируй ссылку заново.

## Режимы subscription-ссылок

Используй один из режимов.

### Закрытый режим

Закрытый режим подходит до настройки публичного subscription endpoint.

- Панель 3x-ui слушает только `127.0.0.1:ПОРТ_ПАНЕЛИ`.
- Порт панели не открыт в `ufw`.
- Профили экспортируются через SSH-туннель администратором.
- Клиентам выдаются одиночные ссылки с `vpn.ДОМЕН`.

Плюс: минимальная поверхность атаки. Минус: при добавлении резервного профиля
нужно переслать обновлённую ссылку или перейти к публичной подписке.

### Публичная подписка через 3x-ui

Публичная подписка нужна, когда ты готов централизованно раздавать несколько
профилей. Не открывай её до первого бэкапа и ротации засвеченных секретов.

Требования:

- subscription endpoint отдаёт только подписки, а не веб-панель;
- ссылка содержит секретный `URI Path`;
- endpoint доступен по HTTPS или через проверенную TLS-прослойку;
- порт панели не открыт наружу;
- `ufw` открывает только тот порт, который реально обслуживает подписки.

В 3x-ui проверь разделы **Настройки панели** и **Подписки**:

1. Укажи публичный домен подписок:

   ```text
   sub.ДОМЕН
   ```

2. Проверь **URI Path** для подписок. Он должен совпадать с путём, который
   выдаётся клиентам.
3. Если 3x-ui показывает отдельный subscription port, зафиксируй его в менеджере
   паролей. В документации 3x-ui для reverse proxy указан дефолтный порт
   подписок `2096`.
4. Не используй порт панели как публичный порт подписки.
5. Не публикуй ссылку, пока не проверишь TLS и `ufw`.

Минимальная проверка на VPS:

```bash
sudo ss -tlnp | grep -E ':443|:ПОРТ_ПОДПИСКИ|:ПОРТ_ПАНЕЛИ'
sudo ufw status
```

Ожидаемо:

```text
*:443                         xray-linux-amd64
127.0.0.1:ПОРТ_ПАНЕЛИ          x-ui
```

Если subscription endpoint слушает отдельный публичный порт, в `ufw` должна быть
явная запись только для этого порта. Если порт не нужен снаружи, он должен быть
закрыт.

После добавления резервного профиля проверь его порт отдельно по runbook этого
протокола.

## Проверка subscription-ссылки

Проверь ссылку сначала на своём устройстве.

1. Скопируй subscription URL из 3x-ui.
2. Убедись, что URL использует домен:

   ```text
   https://sub.ДОМЕН/SECRET_SUB_PATH
   ```

3. Импортируй URL в Hiddify как подписку.
4. Обнови подписку в клиенте.
5. Проверь, что внутри появились нужные профили:

   ```text
   VLESS Reality  vpn.ДОМЕН:443
   ```

   Резервный профиль добавляй в подписку только после отдельной проверки.

6. Подключись к каждому профилю и проверь трафик в панели.

Если Hiddify не определяет формат, скопирована не subscription-ссылка или endpoint
возвращает HTML-страницу вместо конфигурации. Открой ссылку в браузере только на
своём устройстве и проверь, что ответ похож на подписку, а не на страницу логина.

## Переезд на новый IP

При смене VPS:

1. Подними новый сервер по [runbook миграции](migrate-vps.md).
2. Восстанови 3x-ui из бэкапа.
3. Проверь VLESS Reality по временному IP.
4. Переключи DNS:

   ```text
   vpn.ДОМЕН   A   NEW_SERVER_IP
   sub.ДОМЕН   A   NEW_SERVER_IP
   ```

5. Дождись TTL.
6. Обнови подписку в Hiddify.
7. Проверь, что трафик идёт через новый VPS.

## Чек-лист

- [ ] `vpn.ДОМЕН` смотрит на `SERVER_IP`.
- [ ] `vpn.ДОМЕН` в Cloudflare стоит в режиме **DNS only**.
- [ ] VLESS-ссылка содержит `@vpn.ДОМЕН:443`.
- [ ] Панель 3x-ui доступна только через SSH-туннель.
- [ ] Первый бэкап 3x-ui сделан до публичной подписки.
- [ ] Subscription URL использует `sub.ДОМЕН`.
- [ ] В репозиторий не попали ссылки, токены, UUID, пароли и бэкапы.
