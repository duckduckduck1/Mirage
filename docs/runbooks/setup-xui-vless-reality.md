# Ручная настройка 3x-ui и VLESS Reality

Runbook описывает второй рабочий этап после Ansible-bootstrap: установка панели
3x-ui, закрытие панели за SSH-туннелем, создание inbound `VLESS + Reality +
Vision` на порту `443` и первичная проверка клиента.

Команды выполняй на VPS под пользователем `mirage`, если явно не сказано иначе.
Реальные IP, пароли, UUID, API-токены, приватные ключи Reality и пароль базы не
добавляй в git и не передавай во внешние каналы.

## Предварительная проверка

Проверь, что bootstrap уже завершён:

```bash
sudo -n true
sudo ufw status
sudo /usr/sbin/sshd -T | grep -E 'passwordauthentication|kbdinteractiveauthentication|permitrootlogin|pubkeyauthentication'
```

Ожидаемые признаки:

```text
passwordauthentication no
kbdinteractiveauthentication no
pubkeyauthentication yes
22/tcp ALLOW
443/tcp ALLOW
```

Проверь, что порт `443` ещё свободен:

```bash
sudo ss -tlnp | grep ':443' || true
```

Если команда ничего не выводит, порт свободен.

## Установка 3x-ui

Скачай установщик:

```bash
curl -Ls https://raw.githubusercontent.com/MHSanaei/3x-ui/master/install.sh -o /tmp/3x-ui-install.sh
sudo bash /tmp/3x-ui-install.sh
```

При установке выбери:

- **Database Selection**: `SQLite` для небольшого сервера. PostgreSQL
  допустим, но добавляет отдельный сервис и другой сценарий бэкапа.
- **Panel Port**: случайный высокий порт `10000–60000`, не `22`, не `443`, не
  `8388`.
- **Username** и **Password**: сильные значения, не `admin/admin`.
- **WebBasePath**: случайный секретный путь. Сохрани его в менеджере паролей.
- **SSL Certificate Setup**: **Skip SSL**, потому что панель будет доступна
  только через SSH-туннель.
- **Bind the panel to 127.0.0.1 only?**: `y`.

Если случайно ответил не `y`, исправь после установки:

```bash
sudo /usr/local/x-ui/x-ui setting -listenIP 127.0.0.1
sudo systemctl restart x-ui
```

## Проверка панели

Проверь, где слушает панель:

```bash
sudo ss -tlnp | grep 'ПОРТ_ПАНЕЛИ'
```

Ожидаемый результат:

```text
127.0.0.1:ПОРТ_ПАНЕЛИ
```

Порт панели не открывай в `ufw`. Проверка firewall должна показывать только
рабочие сервисные порты:

```bash
sudo ufw status
```

Ожидаемый минимум:

```text
22/tcp ALLOW
443/tcp ALLOW
```

С локальной машины открой SSH-туннель:

```powershell
ssh -N -i $HOME\.ssh\mirage_ed25519 -L 2096:127.0.0.1:ПОРТ_ПАНЕЛИ mirage@SERVER_IP
```

Пока эта команда работает, открой в браузере:

```text
http://localhost:2096/WEB_BASE_PATH
```

`WEB_BASE_PATH` возьми из результата установки или из root-only файла:

```bash
sudo cat /etc/x-ui/install-result.env
```

Файл содержит секреты. Не копируй его целиком в документацию, issue, PR или
внешние каналы.

## Создание inbound VLESS Reality

В панели открой **Входящие** и нажми **Создать подключение**.

На вкладке **Основное**:

| Поле | Значение |
|---|---|
| **Включить** | включено |
| **Примечание** | `vless-reality-vision` |
| **Протокол** | `vless` |
| **Адрес** | пусто, чтобы слушать все адреса |
| **Стратегия адреса для ссылок** | публичный IP сервера или пользовательский адрес |
| **Публичный адрес / адрес для ссылок** | `SERVER_IP`, если поле появилось |
| **Порт** | `443` |
| **Общий расход** | `0` |
| **Сброс трафика** | **Никогда** |
| **Дата окончания** | пусто |

Если после экспорта клиент показывает **Неизвестный IP**, значит ссылка собрана
без публичного адреса. Вернись в inbound, выбери стратегию публичного IP или
укажи `SERVER_IP` как пользовательский адрес, сохрани и экспортируй ссылку заново.

На вкладке **Протокол**:

| Поле | Значение |
|---|---|
| **Расшифрование** | `none` |
| **Шифрование** | `none` |

На вкладке **Поток**:

| Поле | Значение |
|---|---|
| **Транспорт** | `RAW` |
| **Proxy Protocol** | выключено |
| **HTTP Обфускация** | выключено |
| **Sockopt** | выключено |
| **TCP Masks** | не добавлять |

На вкладке **Безопасность** выбери **Reality**:

| Поле | Значение |
|---|---|
| **Xver** | `0` |
| **uTLS** | `chrome` |
| **Цель** | `vk.ru:443` |
| **SNI** | `vk.ru` |
| **Макс. разница во времени (мс)** | `0` |
| **Short IDs** | один сгенерированный short ID |
| **SpiderX** | `/` |
| **Публичный ключ** | сгенерировать |
| **Приватный ключ** | сгенерировать и не раскрывать |
| **mldsa65 Seed / Verify** | пусто |
| **Лог мастер-ключей** | пусто |

`Цель` и `SNI` должны совпадать по домену. Приватный ключ Reality остаётся только
на сервере. Клиенту нужен публичный ключ, который попадёт в `vless://`-ссылку.

Нажми **Создать**.

## Добавление клиента

Если в колонке **Клиенты** стоит `0`, создай клиента:

1. Открой **Клиенты**.
2. Нажми **Добавить клиента**.
3. На вкладке **Основные** укажи:

   | Поле | Значение |
   |---|---|
   | **Email** | `main` или имя устройства |
   | **Лимит трафика (ГБ)** | `0` |
   | **Лимит IP** | `0` |
   | **Срок действия** | пусто |
   | **Автопродление (дней)** | `0` |
   | **Привязанные входящие** | выбери `vless-reality-vision` |
   | **Включить** | включено |

4. На вкладке **Учетные данные** проверь:

   | Поле | Значение |
   |---|---|
   | **UUID** | сгенерирован |
   | **Flow** | `xtls-rprx-vision` |

5. Нажми **Создать**.

Вернись во **Входящие**. В колонке **Клиенты** должно быть `1`.

## Экспорт профиля в Hiddify

В строке inbound нажми меню **⋮** и выбери **Экспорт подключений**. В окне QR
раскрой одиночный профиль **Vless / TCP / REALITY** и скопируй ссылку.

Для первого теста используй именно одиночную ссылку `vless://...`, а не
информацию о подписке.

Перед импортом проверь ссылку в локальном текстовом редакторе. Не передавай её во
внешние каналы. В ней должны быть признаки:

```text
vless://
@SERVER_IP:443
security=reality
type=tcp
flow=xtls-rprx-vision
sni=vk.ru
fp=chrome
pbk=
sid=
```

В Hiddify добавь профиль через clipboard или ручной импорт. Если Hiddify пишет
`unable to determine config format`, значит скопирован не одиночный `vless://`
профиль. Вернись к окну экспорта и скопируй именно ссылку конфигурации.

## Проверка работы

На VPS:

```bash
sudo ss -tlnp | grep -E ':443|:ПОРТ_ПАНЕЛИ'
sudo ufw status
systemctl status x-ui --no-pager
```

Ожидаемые признаки:

```text
*:443                    xray-linux-amd64
127.0.0.1:ПОРТ_ПАНЕЛИ     x-ui
443/tcp ALLOW
x-ui active (running)
```

На локальной Windows-машине:

```powershell
Test-NetConnection SERVER_IP -Port 443
```

Ожидаемый результат:

```text
TcpTestSucceeded : True
```

Если Hiddify показывает timeout, открой логи на VPS:

```bash
sudo journalctl -u x-ui -f
```

Нажми подключение в Hiddify и смотри, появляются ли ошибки. Если порт `443`
доступен, но клиент не подключается, проверь совпадение `SNI`, `flow`, публичного
ключа, `short ID` и публичного адреса в ссылке.

## Что зафиксировано после этапа

- 3x-ui установлен как `systemd`-сервис `x-ui`.
- Веб-панель слушает только `127.0.0.1:ПОРТ_ПАНЕЛИ`.
- Доступ к панели идёт через SSH-туннель на `localhost:2096`.
- Xray слушает публичный `443/tcp`.
- `ufw` открывает `22/tcp` и `443/tcp`, но не открывает порт панели.
- Создан inbound `VLESS + TCP + Reality + Vision`.
- В Hiddify импортирован одиночный `vless://` профиль, подключение проверено
  реальным трафиком.
