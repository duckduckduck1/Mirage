# Стиль документации Mirage

Краткая выжимка правил письма для всей документации проекта. За основу взят
[Google developer documentation style guide](https://developers.google.com/style),
адаптированный под русский язык и под этот проект. Если правило здесь не описано —
смотри оригинал Google.

Цель — единый голос: ясно, дружелюбно, без воды и «магии».

## Голос и тон

- Пиши **дружелюбно, но профессионально** — как опытный коллега объясняет младшему.
- Обращайся к читателю на **«ты»** (единое второе лицо во всём проекте, как в
  учебном гайде). Не смешивай «ты» и «вы».
- Используй **активный залог** и **настоящее время**: «команда открывает порт», а
  не «порт будет открыт командой».

## Ясность

- Одно предложение — одна мысль. Короткие предложения лучше длинных.
- Избегай слов **«просто», «легко», «очевидно», «всего лишь»** — то, что просто
  для автора, может быть сложно для читателя.
- Расшифровывай аббревиатуру при **первом** упоминании: «Deep Packet Inspection
  (DPI)». Дальше — просто «DPI».
- Не используй жаргон без объяснения. Термины выноси в глоссарий.

## Заголовки

- Пиши заголовки в обычном регистре (sentence case), не Капитализируй Каждое Слово.
- Заголовок описывает **задачу или содержание**: «Установка панели 3x-ui», а не
  «Панель».
- Не начинай документ или раздел с местоимения, ссылающегося на заголовок.

## Списки и шаги

- **Нумерованный** список — для последовательности шагов, где порядок важен.
- **Маркированный** список — для набора равнозначных пунктов.
- Начинай пункты одинаково грамматически (все с глагола или все с существительного).

## Код и команды

- Имена файлов, команды, флаги, значения — в `моноширинном шрифте`.
- Блоки кода — с указанием языка для подсветки:

  ````text
  ```bash
  ufw allow 443/tcp
  ```
  ````

- **Плейсхолдеры — ЗАГЛАВНЫМИ** буквами, чтобы их было видно и нельзя было
  скопировать вслепую: `ssh root@SERVER_IP`, `http://SERVER_IP:ПОРТ_ПАНЕЛИ`.
- Объясняй неочевидные флаги рядом с командой или комментарием в блоке.
- Никогда не вставляй в примеры **настоящие** секреты, ключи или пароли.

## Ссылки

- Текст ссылки должен описывать цель: [документация по архитектуре], а не «жми
  сюда» или «здесь».
- Для файлов проекта используй относительные пути.

## Элементы интерфейса

- Названия кнопок, пунктов меню и полей выделяй **жирным**: нажми **Add Inbound**,
  поле **Port**.

## Числа и единицы

- Между числом и единицей — пробел: `1 ГБ`, `443 порт` → лучше «порт 443».
- Диапазоны — через тире: порты `10000–60000`.
